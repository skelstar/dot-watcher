DotWatcher — iOS API Reference

All network calls made by the iOS app to the DotWatcher REST API. For the complete, always-current API surface (including admin/ops endpoints not used by the app), see the server's generated Swagger UI at /swagger in Development.

Base URL: https://dot-watcher.skelstar.io/api  ·  Auth: Bearer token in Authorization header  ·  Token stored in Keychain  ·  Every request sends X-Api-Version

Sections

  • Authentication
  • Sessions
  • Crew
  • Location Tracking
Client compatibility: every call above also sends X-Api-Version: <int> (the apiVersion constant in LocationManager.swift), bumped only when the app adopts a change that could break against the server — not on every release. If the server's configured floor is above what this build sends, it responds 426 Upgrade Required and the app shows a blocking "Update Required" screen (UpdateRequiredView.swift) instead of the normal response shown for each endpoint below. See server/README.md#client-compatibility-x-api-version for the full server-side contract.

Authentication

POST /auth/login No auth

Sign in with username and password. Returns a bearer token and user profile stored in the app for all subsequent calls.

Request Body

{
  "username": "string",
  "password": "string"
}

Response — AuthSession

{
  "accessToken": "string",
  "user": {
    "userId": "string",
    "username": "string",
    "displayName": "string",
    "features": ["crew"]   // what this account can use; [] when none. Older builds ignore it
  }
}
POST /auth/register No auth

Create a new account. Returns the same AuthSession structure as login — the user is immediately signed in.

Request Body

{
  "username": "string",
  "password": "string",
  "displayName": "string"
}

Response — AuthSession

{
  "accessToken": "string",
  "user": { ... }
}
POST /auth/logout Bearer token

Revoke the current access token on the server, then clear it from the Keychain. Called when the user signs out.

Request Body

Empty

Response

Empty / ignored

DELETE /me Bearer token

Permanently delete the authenticated user's account and all associated data.

Request Body

Empty

Response

Empty

Sessions

GET /me/sessions Bearer token

Load all sessions the current user belongs to, including their role and the invite code for each. Called on app launch, after sign-in, and whenever the session sheet opens.

Request Body

None

Response — [SessionMembership]

[{
  "sessionId": "string",
  "sessionName": "string",
  "inviteCode": "string",
  "role": "runner" | "viewer",
  "displayName": "string"
}]
POST /sessions Bearer token

Create a new session. The caller becomes the owner. An invite code is generated server-side and returned in the response. With "nearby": true (accounts with the events feature only; 400 otherwise) people near the caller can find and join the session without a code: sessionName then becomes a public title of 1–30 characters (case and spaces kept, not the invite code), and a position is required, which becomes the first meeting point. Without nearby, sessionName keeps its 4–8 character rule.

Request Body

{
  "sessionName": "string | null",
  "displayName": "string | null",
  "maxLengthHours": 1–240 | null,
  "nearby": true | null,
  "nearbyRadiusMeters": 50 | 100 | 250 | 500 | null,   // default 100
  "latitude": number | null,    // required with nearby
  "longitude": number | null,   // required with nearby
  "accuracy": number | null     // metres; 100 or better with nearby
}

Response — SessionMembership

{
  "sessionId": "string",
  "sessionName": "string",
  "inviteCode": "string",
  "role": "runner",
  "displayName": "string"
}
POST /session-invites/{inviteCode}/join Bearer token

Join an existing session using a 6-character invite code (uppercase). The role is caller-selected, not owner-granted: omit it (or send anything other than "runner") to join as viewer, or send "runner" to join as runner outright.

Request Body

{
  "displayName": "string | null",
  "role": "runner" | "viewer" | null
}

Response — SessionMembership

{
  "sessionId": "string",
  "sessionName": "string",
  "inviteCode": "string",
  "role": "runner" | "viewer",
  "displayName": "string"
}
PUT /sessions/{sessionId}/nearby Bearer token

Owner only. The organiser's “Ping”: a fresh fix moves the session's meeting point (it never moves on its own and needs no tracking), and enabled / radiusMeters change whether people nearby can find the session and how far away they can be. A fix is required unless the call is only "enabled": false. Giving a radius to a session with nearby off turns it on. Switching off hides the session from discovery; existing members stay. 404 without the events feature; 403 if the caller isn't the owner or the id is unknown; 410 if the session has ended; 400 for a bad fix (accuracy worse than 100 m) or radius. Coordinates are never returned.

Request Body

{
  "latitude": number | null,
  "longitude": number | null,
  "accuracy": number | null,
  "enabled": true | false | null,
  "radiusMeters": 50 | 100 | 250 | 500 | null
}

Response

{
  "nearby": true | false,
  "radiusMeters": 100
}
GET /me/events/nearby?lat=&lon=&accuracy= Bearer token

What is happening near the caller. With lat and lon, lists sessions the caller can join from where they are, nearest first, at most 10. A session is listed when nearby is on, it hasn't ended, and the caller is inside its radius (each fix's accuracy, in metres, is forgiven up to 50 m; a missing accuracy forgives nothing). Sessions the caller is already in, or whose organiser they are blocked with either way, are left out. Distance is rounded to 50 m and no coordinates are returned. Without lat/lon it returns the old single placeholder event. 404 without the events feature; 400 for an invalid position; 429 after 120 lookups per user per hour (position-less calls are never limited).

Request Body

None

Response

[{
  "id": "session-<sessionId>",
  "eyebrow": "Happening near you · 100 m",
  "title": "Sunday long run",
  "subtitle": "Organised by Alice",
  "sessionId": "string | null"   // null on the placeholder, which can't be joined
}]
POST /nearby/sessions/{sessionId}/join Bearer token

Joins a session from the nearby list, as a runner, with no invite code. The server re-checks the caller's position against the session's radius. Every refusal (unknown, not nearby, switched off, ended, blocked, too far) is the same 404 so it can't be used to probe. 404 without the events feature; 400 for a missing or invalid position; 429 after 20 attempts per user per hour.

Request Body

{
  "latitude": number,
  "longitude": number,
  "accuracy": number | null,
  "displayName": "string | null"
}

Response — same shape as the invite join

{
  "sessionId": "string",
  "sessionName": "string",
  "inviteCode": "string",
  "role": "runner",
  "displayName": "string",
  "ownerDisplayName": "string",
  "participants": [...]
}
DELETE /me/sessions/{sessionId}/membership Bearer token

Removes the caller's own membership from a session (leave). Callable by any member, not just the owner — a session's owner is attribution only and has no extra permissions over other members. Deleting a whole session is an admin-only operation (see DELETE /admin/sessions/{sessionId}), not something the owner can call directly.

Request Body

Empty

Response

Empty

Crew

GET /me/crew Bearer token

The caller's crew: people they have added (or who added them) by redeeming a crew code. Mutual and tied to the account, not to a device or session. Pairs where either person has blocked the other are never listed. Usernames are deliberately not included.

Request Body

None

Response

{
  "crew": [{
    "userId": "string",
    "nickname": "string" | null,   // falls back to displayName (initials) when null
    "displayName": "string",
    "since": "ISO 8601 UTC"
  }]
}
DELETE /me/crew/{userId} Bearer token

Removes someone from the caller's crew, for both people, immediately. The other person is not notified. 404 if they weren't in the crew.

Request Body

None

Response

Empty (204)

POST /me/crew/codes Bearer token

Creates a one-time crew code for the caller to send to one person. 8 characters (no 0/O/1/I/L), valid 24 hours, works once. A user can hold three live codes; creating a fourth retires the oldest. Clients build the share link (https://<web host>/crew/{code}) themselves.

Request Body

None

Response

{ "code": "string", "expiresAt": "ISO 8601 UTC" }
GET /me/crew/codes Bearer token

The caller's unused, unexpired crew codes, newest first, so "Show my code" can keep showing the same one.

Request Body

None

Response

[{ "code": "string", "expiresAt": "ISO 8601 UTC" }]
DELETE /me/crew/codes/{code} Bearer token

Revokes one of the caller's unused crew codes. 404 if it isn't theirs or is already used.

Request Body

None

Response

Empty (204)

GET /me/crew/codes/{code} Bearer token

Says whose code this is, for the "Add Priya to your crew? They'll see you too." confirmation. Adds no one. Rate-limited (20 previews and redemptions per user per hour; 429). An unknown, expired, used, malformed or blocked code all return the same 404; the caller's own code returns 400.

Request Body

None

Response

{
  "userId": "string",
  "nickname": "string" | null,
  "displayName": "string",
  "alreadyCrew": true | false
}
POST /me/crew/codes/{code}/redeem Bearer token

Redeems a crew code: the caller and the code's owner become crew immediately. The first valid redeemer wins (the claim is one conditional update); everyone else gets the same 404 as for an unknown code. Redeeming for someone who is already crew succeeds without using the code up. 409 if either person's crew is full (50). Same rate limit and errors as the preview.

Request Body

None

Response — the code owner as a crew member

{
  "userId": "string",
  "nickname": "string" | null,
  "displayName": "string",
  "since": "ISO 8601 UTC"
}
GET /me/profile Bearer token

The nickname the caller's crew sees for them (null when unset). Like every crew endpoint, 404 when the account doesn't have the crew feature.

Request Body

None

Response

{ "nickname": "string" | null }
PUT /me/profile Bearer token

Sets the nickname, or clears it when null or blank. Trimmed, at most 30 characters, no control characters (400 otherwise).

Request Body

{ "nickname": "string" | null }

Response

{ "nickname": "string" | null }

Location Tracking

POST /location Bearer token Every 15 s

The core tracking call. Sends the runner's current GPS position to the server during an active tracking session. Fires every 15 seconds, aligned to epoch-based intervals. The response returns all current participant positions — this is the only way the app polls for live session state while tracking.

Request Body

{
  "runnerName": "string",
  "sessionId": "string",
  "latitude": number,
  "longitude": number,
  "heading": number,   // omitted if < 0
  "timestamp": "ISO8601"
}

Response — LocationPostResponse

{
  "participants": ["string"],
  "positions": [[{
    "runnerName": "string",
    "latitude": number,
    "longitude": number,
    "heading": number,
    "timestamp": "ISO8601"
  }]]
}
Role requirement: Only users with membership role runner can post location updates. A session's owner has no special write access beyond that — their own membership just happens to be created with role runner too. positions is the same shape as GET /locations/{sessionId}, included here so the app can render the map from this response alone.
POST /location Bearer token

Presence announcement — same endpoint as the tracking call, but sent once immediately when the user selects a session. Sends zero coordinates (lat: 0, lon: 0) so the server registers the user as active in the session before tracking starts.

Request Body

{
  "runnerName": "string",
  "sessionId": "string",
  "latitude": 0.0,
  "longitude": 0.0,
  "timestamp": "ISO8601"
}

Response

LocationPostResponse (ignored)

GET /locations/{sessionId} Bearer token

Fetch the current positions of all participants in a session. Called once when the user selects a session to pre-populate the map before the tracking loop begins.

Request Body

None

Response — [[RunnerPositionResponse]]

[[{
  "runnerName": "string",
  "latitude": number,
  "longitude": number,
  "heading": number,
  "timestamp": "ISO8601"
}]]
Response is an array of arrays — each inner array is one runner's position history (most recent first). The outer array groups by runner.
