DotWatcher — Database Schema

SQLite database (dotwatcher.db) managed by SessionStore.cs. WAL journal mode enabled.

All timestamp columns store ISO 8601 strings (TEXT). All ID columns are either GUIDs or hex strings.

Relationships at a glance

users

  • ↓ owns many app_sessions
  • ↓ member of many session_members
  • ↓ posts many location_updates

app_sessions

  • ↑ owned by one users
  • ↓ has many session_members
  • ↓ has many location_updates

session_members

  • ↑ belongs to one app_sessions
  • ↑ belongs to one users
  • role: owner | runner | viewer

location_updates

  • ↑ belongs to one app_sessions
  • runner_user_id is nullable
  • NULL = imported recording, not live tracking

revoked_user_tokens

  • Standalone — no FK to users
  • Expired rows are pruned on each check

Tables

users SQLite

One row per registered account. The root of all FK relationships.

Column Type Constraints Notes
id TEXT PKNOT NULL GUID generated at registration
username TEXT NOT NULLUNIQUE Login handle, case-sensitive
display_name TEXT NOT NULL Shown to other users
password_hash TEXT NOT NULL BCrypt hash — never returned to client
created_at TEXT NOT NULL ISO 8601, set at insert, never updated

Indexes

idx_users_username ON (username)
app_sessions SQLite

A tracking session created by an owner. The owner is always also a member in session_members with role owner.

Column Type Constraints Notes
id TEXT PKNOT NULL GUID generated at creation
session_name TEXT NOT NULL Normalised to uppercase alphanumeric + - _, 3–32 chars
invite_code TEXT NOT NULLUNIQUE 6-char random hex string (uppercase). Shared with runners to join
owner_user_id TEXT NOT NULLFK → users(id) Denormalised for fast owner lookups without joining session_members
created_at TEXT NOT NULL ISO 8601. Used by browse query to filter to "today" only

Indexes

idx_app_sessions_invite ON (invite_code)
session_members SQLite

Junction table linking users to sessions with a role. A user can belong to multiple sessions. The owner appears here with role owner — this role is immutable via the API.

Column Type Constraints Notes
session_id TEXT PK (composite)FK → app_sessions(id)
user_id TEXT PK (composite)FK → users(id) Composite PK enforces one membership per user per session
role TEXT NOT NULL owner — created by, immutable
runner — can post locations
viewer — read-only, joins via invite or request
display_name TEXT NOT NULL Name shown on the map for this member in this session. Can differ from users.display_name
joined_at TEXT NOT NULL ISO 8601. Members are listed in join order

Indexes

idx_session_members_user ON (user_id)
Role permissions: only owner and runner may post location updates (CanWriteLocation). The owner role cannot be changed via UpdateSessionMemberRole — it is set once at session creation and never altered.
location_updates SQLite + In-memory cache

Every GPS position posted during a live session, plus imported recordings. Also mirrored in the in-memory _sessions dictionary for low-latency reads during active tracking.

Column Type Constraints Notes
id INTEGER PKAUTOINCREMENT Insertion order is preserved; used for ORDER BY in recordings
session_id TEXT NOT NULL References app_sessions.id — no FK constraint, allowing orphan rows for imported recordings
runner_user_id TEXT NULLABLE NULL for imported/replayed recordings. Set to the posting user's id for live tracking
runner_name TEXT NOT NULL Display name at the time of posting — denormalised so recordings remain readable after account changes
latitude REAL NOT NULL WGS-84 decimal degrees
longitude REAL NOT NULL WGS-84 decimal degrees
heading REAL NULLABLE Degrees 0–360. Omitted by the iOS app when the device reports a negative course (no reliable heading)
timestamp TEXT NOT NULL ISO 8601 from the device clock, not the server receive time

Indexes

idx_session ON (session_id) idx_session_runner ON (session_id, runner_name)
In-memory cache: live positions are also held in ConcurrentDictionary<sessionId, ConcurrentDictionary<userId, List<RunnerPosition>>>. The cache is the primary read path for GET /locations/{sessionId} and the location POST response — SQLite is only queried for recordings and admin views. The cache is lost on server restart.
revoked_user_tokens SQLite

Denylist for bearer tokens that have been explicitly signed out before their natural expiry. Expired rows are automatically pruned on every read or write to keep the table small.

Column Type Constraints Notes
token_id TEXT PKNOT NULL The JWT jti claim uniquely identifying the token
expires_at TEXT NOT NULL Copied from the token's own expiry — used to prune stale rows
revoked_at TEXT NOT NULL Server time of the logout call

Indexes

idx_revoked_user_tokens_expires_at ON (expires_at)
No FK to users — a revoked token must remain valid even after the user account is deleted, until the token's natural expiry passes.

In-memory cache (live tracking only)

_sessions In-memory only

Held in SessionStore as a nested ConcurrentDictionary. Populated as runners post location updates. Cleared on server restart — SQLite is the source of truth for historical data.

Key / Field Type Notes
outer key string Session ID (app_sessions.id)
inner key string User ID (users.id)
value List<RunnerPosition> Append-only position history for this runner in this session. Only the last entry is used for GetLatestPositions
RunnerPosition.RunnerName string Display name at time of post
RunnerPosition.Latitude double WGS-84
RunnerPosition.Longitude double WGS-84
RunnerPosition.Heading double? Nullable — absent when device has no reliable course
RunnerPosition.Timestamp DateTimeOffset Device clock time from the POST body
Live participant lists and current positions are served entirely from this cache — SQLite is not queried for real-time reads. After a server restart the cache is empty until runners start posting again, so GET /locations/{sessionId} will return no positions until the next location POST arrives.

Deletion cascades

SQLite FK cascades are not used. All deletions are handled explicitly in SessionStore within transactions.

Trigger Rows deleted
Delete session (DELETE /me/sessions/{id}) location_updates WHERE session_id
session_members WHERE session_id
app_sessions WHERE id
In-memory _sessions[sessionId] evicted
Delete user account (DELETE /me) location_updates WHERE runner_user_id (own posts)
For each owned session: location_updates, session_members, app_sessions
session_members WHERE user_id (non-owned memberships)
users WHERE id
In-memory cache evicted for owned sessions; user entry removed from shared sessions
Note for the stop-and-leave feature: DELETE /me/sessions/{id} is currently owner-only and deletes the entire session including all members and location history. A non-owner "leave session" flow will require a separate endpoint (e.g. DELETE /me/sessions/{id}/membership) that only removes the calling user's row from session_members.
